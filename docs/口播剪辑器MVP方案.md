# 口播剪辑器 MVP 方案

> 日期：2026-08-11  
> 状态：已确认，作为 `jc-koubojianji-desk` 的首版开发合同

## 1. 产品定位

口播剪辑器面向已录完但表达松散、重复或顺序混乱的口播视频。它不生成新内容，不替用户改写事实；它把用户确认过的原话整理为可审核的剪辑计划，并据此输出带字幕的视频。

首版只有两个工作台：

```text
字幕工作台 -> 结构编辑工作台（生成预览 -> 导出成片）
```

不新增单独的“成片工作台”。生成预览和导出是结构编辑工作台底部的收口动作。

## 2. 首版边界

### 必须完成

1. 上传原始口播视频，识别出带时间码的字幕。
2. 用户逐条修正并确认原话。
3. 模型根据确认稿和用户意见提出结构整理方案。
4. 用户审核、拖拽重排、删除或恢复原片段。
5. 按确认方案生成剪辑预览，并导出带基础字幕的成片。

### 明确不做

- 不翻译、不配音、不做角色或音色管理。
- 不让模型凭空增加、改写或拼接原话。
- 不做多轨时间线、画中画、B-roll、转场、调色或自动包装。
- 不做背景音乐和自动混音。
- 不在首版渲染花字；只保留数据位置。

## 3. 工作台职责

### 3.1 字幕工作台：确认事实

沿用现有字幕工作台的视觉密度和操作习惯：9:16 视频预览、时间码、识别原文、人工确认稿、逐行定位、识别字幕、大模型语义校准，以及播放头新增、拆分、合并、调整边界和删除字幕。语义校准提供可直接编辑的要求输入框；用户可把常用要求保存为个人预设，点击预设只负责回填输入框，再点击“字幕校准”才执行。

口播剪辑器只保留与事实确认有关的字段：

```text
序号 | 时间轴 | 片段预览 | 识别原文 | 人工确认稿
```

不带入抽帧校准、翻译、目标语言、说话角色、配音或成片母版等翻译专属概念。确认完成后，原始字幕仅可回到本工作台编辑；结构编辑工作台只读它。

大模型语义校准必须是审核流程：先按选定模板生成每条字幕下的校准建议，用户点击“应用校准建议”后才替换人工确认稿；支持“撤销本次校准”和“恢复并采用 FunASR 原文”。

### 3.2 结构编辑工作台：组织表达

结构编辑工作台负责把确认稿变成一份可执行的剪辑计划。它不直接修改原始字幕，也不持有孤立的改写文案。

布局固定为三栏，成片操作放在右栏：

```text
成片预览（9:16） | 整理后口播稿（可编辑） | 编辑意见与模型操作
```

- 左栏：播放当前剪辑计划生成的 9:16 成片；生成前显示待生成状态，生成后直接在此预览，不要求用户打开本地文件。
- 中栏：按输出顺序显示段落标题和保留片段。用户可拖拽排序、删除片段、恢复删除片段、修改段落标题。
- 右栏：编辑意见输入框、可点击的口播整理模板、`生成整理方案`、`还原示例方案`、`字幕样式`、`花字模板`和`生成成片`。
- 点击模板必须把模板完整写入编辑意见输入框；点击生成后直接更新中栏的整理后口播稿，不另开方案框。
- `生成成片`是唯一生成动作，完成剪辑、烧录基础字幕并把结果放入左栏播放；首版不区分“预览”和“导出”。花字模板先作为设置入口，实际渲染留给后续阶段。

同一时间只突出一个主按钮。删除、恢复、重新生成均为次级或文字按钮，颜色、间距、图标和禁用状态沿用现有产品规范。

## 4. 数据合同

### 4.1 原始字幕是唯一事实来源

```ts
interface SourceCue {
  cueId: string
  startMs: number
  endMs: number
  recognizedText: string
  confirmedText: string
}
```

- `cueId` 在一次源视频生命周期内稳定且唯一。
- `startMs`、`endMs` 只在字幕工作台编辑。
- 结构编辑工作台不得复制一份可独立漂移的“原稿”。
- 更换视频或修改任一确认稿时，当前剪辑计划和预览必须标记为过期，不能继续导出。

### 4.2 剪辑计划是唯一执行输入

```ts
interface EditBlock {
  blockId: string
  heading: string
  cueIds: string[]
}

interface OverlayAnnotation {
  annotationId: string
  cueId: string
  text: string
  startOffsetMs: number
  endOffsetMs: number
  kind: 'emphasis'
}

interface EditPlan {
  sourceFingerprint: string
  sourceScriptHash: string
  blocks: EditBlock[]
  removedCueIds: string[]
  annotations: OverlayAnnotation[]
}
```

- `EditBlock.cueIds` 的顺序就是成片播放顺序。
- 每个保留的 `cueId` 最多出现一次；删除项只存在于 `removedCueIds`。
- 每个 `cueId` 必须属于当前确认稿，不能引用模型虚构的内容。
- 第一版 FFmpeg 按完整 cue 边界剪辑，不处理词级切点，避免截断说话。
- `sourceFingerprint` 和 `sourceScriptHash` 用于拒绝过期计划。

`annotations` 是未来花字的预留。模型可以在方案中提出重点建议，但首版不生成或渲染它；用户确认后才允许进入后续版本的渲染链路。

### 4.3 模型输出边界

模型的输出必须经过程序校验，只能包含：

- 段落标题；
- 已有 `cueId` 的保留、删除和排序；
- 删除理由；
- 可选的花字候选建议。

模型不得输出新的正文作为执行依据。中栏显示的正文始终由引用的 `confirmedText` 拼出；若用户需要改字，必须返回字幕工作台修改原话。

## 5. 状态流转

```text
未上传
-> 已识别
-> 字幕已确认
-> 有草稿剪辑计划
-> 计划已确认
-> 预览已生成
-> 成片已导出
```

- 修改字幕：使剪辑计划、预览和成片过期。
- 修改剪辑计划：使预览和成片过期。
- 修改导出字幕样式：只使预览和成片过期，不使剪辑计划过期。
- 模型生成失败、预览失败或导出失败：保留上一次可用确认稿和计划，并展示可重试状态。

## 6. 字幕、花字与音乐

### 6.1 基础字幕

首版导出默认烧录基础字幕，内容来自保留 `cueId` 对应的 `confirmedText`。重排后字幕时间码按新视频时间轴重新计算。

### 6.2 花字

花字是后续功能，不等同于普通字幕。它应以 `OverlayAnnotation` 绑定原始 cue 和片段内偏移时间，避免剪辑重排后定位丢失。首版仅保留合同，不显示入口、不渲染。

### 6.3 音乐

音乐未来放在结构编辑工作台底部的“成片设置”内，不另设页面。加入时必须有来源选择、启用开关、音量控制和自动压低人声音量的混音规则；在这些条件确定前不做占位按钮。

## 7. 开发节奏

### 阶段 A：静态 UI 原型

实现两个工作台、顶部切换、三栏结构编辑页面和完整按钮状态，但不接模型、不接 FFmpeg。验收标准：可用假字幕查看、拖拽、删除/恢复、编辑意见和预览/导出状态流转。

### 阶段 B：字幕承接与本地计划

接入现有 ASR、视频预览和字幕确认能力；把确认稿转换为 `SourceCue`，保存和校验 `EditPlan`。验收标准：重新打开项目后，确认稿和人工调整后的计划不丢失，修改确认稿会使计划过期。

#### 阶段 B.1：字幕工作台按钮后端清单

开发按一个界面一个界面推进。字幕工作台先完整闭环；结构编辑、模型整理和 FFmpeg 成片在其后接入。主线已有的 FunASR、字幕编辑、语义校准、视频预览、媒体路径校验和 FFmpeg 只复用底层能力，不能复制视频翻译的剧集、角色、翻译、配音或 Wiki 业务状态。

每个按钮实现前必须明确：输入、写入产物、失败表现，以及会被标记过期的下游结果。

设置是全局基础设施，沿用主线已验证的实现：韭菜盒子 API Key 的保存与连接测试、文本模型选择、前往 Key 管理页，以及 FunASR 本地字幕引擎的一键安装和安装进度。它不写入项目字幕或剪辑计划；项目内只记录模型实际执行时的输入输出与模型名。

| 界面动作 | 输入与处理 | 项目内产物 | 完成标准 |
| --- | --- | --- | --- |
| 新建项目 / 打开项目 | 用户选择项目根目录，创建并读取项目描述 | `文档/项目.json` | 四个媒体目录存在，重新打开后仍定位同一项目 |
| 右上角设置 | API Key、文本模型、FunASR 安装状态 | 全局安全存储与应用运行时 | 可保存和测试 Key；可前往 Key 管理页；一键安装的状态和进度可见 |
| 导入原视频 | 选择单个可读视频，校验视频流与时长，复制为受控原片 | `视频/原始口播.<ext>`、`文档/项目.json` | 左栏可直接播放；替换原片会使字幕、计划和成片过期 |
| 识别字幕 | 受控原片 -> FFmpeg 提取音频 -> FunASR | `视频/原始口播.wav`、`文档/原始转写.json`、`文档/原始转写.srt` | 保留稳定 `cueId`、时间码和 FunASR 原文；失败可重试且不覆盖上次成功结果 |
| 编辑人工确认稿 | 修改单条确认文本 | `文档/确认字幕.json`、`文档/确认字幕.srt` | 原始转写不被改写；修改后旧计划和成片立即过期 |
| 字幕校准 | 完整原文、校准要求、个人预设文本 -> 模型建议 | `文档/字幕校准记录.json` | 仅生成逐条建议；未点击“应用校准建议”不得改确认稿 |
| 应用 / 撤销 / 恢复原文 | 用户选择建议、撤销本次建议或恢复 FunASR 原文 | `文档/确认字幕.json`、`文档/字幕校准记录.json` | 所有变更可追溯；任何确认稿变化均使计划和成片过期 |
| 新增 / 拆分 / 合并 / 调整边界 / 删除 | 基于播放头与选中 `cueId` 修改 `SourceCue` | `文档/确认字幕.json`、`文档/确认字幕.srt` | cueId 唯一、时间有效；操作失败不写半份字幕文件 |
| 确认进入结构编辑 | 校验至少一条有效确认字幕 | `文档/确认字幕.json` | 只有有效确认稿可进入；结构编辑只读该确认稿 |

预设属于用户的操作偏好，而不是项目事实。阶段 B 的第一轮只保证当前工作台会话可保存和加载；持久化时应写入 `文档/项目.json` 的 `preferences` 字段，不能写入 `wiki/` 或其他应用数据目录。

### 阶段 C：模型整理

接入结构化模型输出和合同校验。验收标准：模型无法引用未知 cue、无法创建新正文；用户意见不会覆盖已确认计划。

### 阶段 D：预览与导出

用 FFmpeg 按 `EditPlan` 截取、拼接、烧录基础字幕，分别生成预览和最终导出。验收标准：输出顺序与计划一致、删除项不出现、字幕与新时间轴一致。

## 8. 隔离原则

口播剪辑器是独立桌面 App：独立应用名、构建标识、用户数据目录和项目存储根。可复用经验证的 Electron、FunASR、FFmpeg、媒体路径校验和视频预览底层代码；不得耦合或修改视频翻译的业务状态、角色、配音、混音或成片流程。

### 8.1 项目文件夹是唯一产物根

用户选择的项目文件夹就是项目根目录。App 必须且只能在其下创建：

```text
.raw/jc-media/
  视频/   原始视频、剪辑预览、最终成片
  文档/   项目.json、确认字幕、校准记录、剪辑计划、模型输入输出
  图片/   后续封面、花字图片等图片资产
  音频/   后续音乐、音频分析和混音资产
```

不得再向项目根、`wiki/`、`episodes/` 或其他自定义目录写入口播剪辑器的媒体和文档产物。顶部项目栏首版只提供新建、打开、切换、重命名和在访达显示；不引入剧集层。
