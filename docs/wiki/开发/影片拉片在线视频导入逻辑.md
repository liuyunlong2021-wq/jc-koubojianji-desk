# 影片拉片在线视频导入逻辑

> 按 2026-08-24 `codex/online-video-import` 分支提交 `60d5c21` 的实际代码、TDD-15 与当前会话验证记录。该功能只扩展原片来源，不新建一套网络拉片工作流。

## 功能定位

影片拉片支持两种原片来源：

1. 本地影片：继续使用文件选择器。
2. 视频链接：用户粘贴公开单条视频 URL，App 使用内置 yt-dlp 下载，然后交给本地原片的同一导入函数。

网络视频导入成功后，自动切镜、人工校正、确认镜头、画面反推、资产分析、资产提示词、视频反推、全片总览和导出继续使用 [[开发/影片拉片工作台按钮与后端逻辑]] 记录的原有链路。

## 当前范围

### 支持

- `http:` 和 `https:` URL。
- 公开、单条、非直播视频。
- 不超过 1080p 的最佳视频流与最佳音频流；如需合并，复用 App 现有内置 FFmpeg。
- 实时显示可解析的 yt-dlp 下载百分比。
- 停止当前下载，并保护项目旧原片和旧分析结果。

### 不支持

- 播放列表、直播和多链接队列。
- 登录、Cookie、会员或私密内容；不自动读取浏览器 Cookie。
- 清晰度选择、下载历史、断点续传和独立下载管理器。
- 任意网页图片导入。yt-dlp 不作为通用图片下载器；独立图片组输入需另设数据和 UI 合同。

## 前端交互

### 导入影片

原来的“上传影片”改为一个绿色“导入影片”菜单：

| 菜单项 | 作用 |
| --- | --- |
| 本地影片 | 调用原有 `chooseSource()` 和 Electron 文件选择器。 |
| 视频链接 | 打开“导入视频链接”对话框。 |

已有原片时，文件名右侧的“更换影片”使用同一菜单，不存在另一套更换逻辑。

### 导入视频链接对话框

对话框只包含：

- 一个视频 URL 输入框。
- “仅支持公开的单条视频。请仅下载有权使用的内容。”提示。
- 未开始时的“取消”和“下载并导入”。
- 下载时的进度文字和“停止下载”。
- 失败时的对话框内错误信息。

下载开始前的逻辑：

1. 空 URL 不启用主按钮。
2. 未选择项目时，先调用现有“选择项目”流程；用户取消后不下载。
3. 前端设置 `downloadingSource=true`，对话框进入持续状态，不能误点背景关闭。
4. 下载时工作台中栏和右栏禁止操作，避免与更换原片同时修改下游状态。

成功后 `applySource()` 统一完成：

- 记住项目。
- 更新原片文件名和指纹。
- 清空前端镜头、资产、总览、确认状态和当前镜头选择。
- 清空 URL、关闭对话框，显示“视频已下载并导入”。

失败时保留 URL，方便用户直接重试。离开页面时若仍在下载，前端会发送停止请求。

## IPC 与 Preload

### 渲染层 API

`window.electron.filmBreakdownProject` 新增：

```ts
downloadSource(rootPath: string, url: string)
stopSourceDownload()
```

`electron/preload.ts` 继续使用 `filmInvoke()` 对 IPC 参数做可克隆处理。`electron/electron-env.d.ts` 定义成功结果与本地 `chooseSource()` 一致：`rootPath`/`name`/`fileName`/`fingerprint`/`durationMs`。

### IPC 通道

| 通道 | 处理 |
| --- | --- |
| `film-breakdown-source-download` | 传入项目路径和 URL，调用 `downloadFilmBreakdownSource()`，通过现有 `film-breakdown-progress` 发送进度。 |
| `film-breakdown-source-download-stop` | 调用 `stopFilmBreakdownSourceDownload()`。 |

进度复用影片拉片现有事件总线，没有新建下载事件或任务管理器。

## 后端主链

### 唯一原片导入入口

`chooseFilmBreakdownSource()` 现在只负责选择本地文件与项目，然后调用：

```ts
importFilmBreakdownSource(rootPath, sourceFile)
```

该函数是本地影片与网络下载文件唯一的项目写入链：

1. `inspectVideo()` 使用内置 FFmpeg 读取第一条视频轨与时长；不可读取时在清空旧数据前失败。
2. 使用已验证源文件的扩展名形成 `拉片原片.<ext>`。
3. 先复制到项目视频目录的 UUID 临时文件，再原子重命名。
4. 计算目标文件 SHA-256。
5. 清理旧的拉片分析片段、中间帧和三帧图片目录。
6. 原子写入新 `source`，并清空镜头、资产、总览和边界确认状态。

因此网络来源不能绕过视频校验，也不会形成另一份项目状态或下游分支。

### 下载流程

`downloadFilmBreakdownSource()` 的实际顺序：

```text
拒绝已有活动下载
  → 校验 URL
  → 确认项目
  → fs.mkdtemp() 创建唯一临时目录
  → 建立唯一 AbortController
  → spawn(yt-dlp, args, shell=false)
  → 解析 after_move:filepath
  → 路径与真实路径双重越界检查
  → importFilmBreakdownSource()
  → finally 释放控制器并递归清理临时目录
```

该 MVP 只允许一个活动下载，使用模块级 `sourceDownloadController`，没有任务队列。“停止下载”调用 `abort()`，子进程收到 `SIGTERM`。

### yt-dlp 参数

`buildOnlineVideoDownloadArgs()` 生成固定参数：

```text
--no-playlist
--match-filter !is_live
--newline
--progress
--no-colors
--no-part
--restrict-filenames
--format bv*[height<=1080]+ba/b[height<=1080]/b
--ffmpeg-location <内置 FFmpeg 路径>
--output <临时目录>/source.%(ext)s
--print after_move:filepath
<已校验 URL>
```

- `--no-playlist` 防止链接扩张成多视频。
- `--match-filter !is_live` 拒绝直播。
- 格式表达式优先合并不超过 1080p 的最佳视频和音频，然后回退到带音频单文件。
- `getFFmpegPath()` 校验并返回现有 `ffmpeg-static` 路径，不引入第二个 FFmpeg。
- 输出名固定为 `source.%(ext)s`，视频标题、上传者和 URL 都不参与文件路径生成。
- URL 是 `spawn()` 参数数组最后一项，不进入 shell 字符串。

## 信任边界与数据保护

### URL 校验

`validateOnlineVideoUrl()` 会：

1. 去掉首尾空白。
2. 要求 URL 可由标准 `URL` 解析。
3. 仅允许 `http:` 和 `https:`。
4. 拒绝在 URL 中嵌入用户名或密码。

渲染层按钮门禁只是交互保护；主进程的上述校验才是真实安全边界。

### 文件与项目保护

- 下载目录由 `fs.mkdtemp()` 在系统临时目录中创建。
- yt-dlp 返回路径必须位于当前临时目录内且文件存在。
- 对临时目录和下载文件各执行 `realpath()`，再检查一次，拒绝符号链接跳转。
- 下载失败、用户停止或 FFmpeg 验证失败都在共用导入函数清空旧数据之前结束。
- 临时目录无论成功失败都删除。
- 项目 JSON 不保存原站 URL，App 不保存下载历史。

## 错误与恢复

| 场景 | 当前行为 |
| --- | --- |
| URL 为空、无法解析、协议错误或内嵌凭据 | 报“请输入有效的 HTTP(S) 视频链接”。 |
| 已有活动下载 | 报“已有视频正在下载”。 |
| 内置 yt-dlp 文件不存在 | 报“内置视频下载组件不可用，请重新安装应用”。 |
| 直播 | 报“暂不支持直播链接”。 |
| yt-dlp 返回 Cookie/登录类错误 | 报“该视频需要登录，当前仅支持公开视频”。 |
| 新片场作品页返回 HTTP 403 | 当前进入通用失败提示；站点在网页解析阶段拒绝 yt-dlp 请求，未进入视频流下载，不是项目或 FFmpeg 故障。 |
| 其他站点或网络失败 | 报“视频下载失败，请检查链接和网络后重试”。 |
| 用户停止 | 子进程结束后报“下载已停止”，保留旧项目。 |
| 下载成功但无有效路径或路径越界 | 拒绝导入，清理临时目录。 |
| FFmpeg 不能读取视频 | 共用导入函数失败，不清空旧项目。 |

## yt-dlp 内置和构建

### 固定版本

`build/scripts/setup-yt-dlp.js` 固定 yt-dlp `2026.08.19`，为当前平台选择官方独立发行文件：

- macOS：`yt-dlp_macos`。
- Windows x64/arm64：`yt-dlp.exe` / `yt-dlp_arm64.exe`。
- Linux x64/arm64：`yt-dlp_linux` / `yt-dlp_linux_aarch64`。

脚本先使用固定 GitHub 转发地址，失败后回退到 GitHub 官方发行地址。无论来自哪个下载通道，都必须与脚本内固定的官方 SHA-256 一致才重命名为最终可执行文件。

`runtime/yt-dlp/` 是构建工件，被 `.gitignore` 排除，不把约 37MB 的 macOS 二进制提交到 Git。`prebuild` 会在正式构建前运行安装/校验脚本，也可手动执行 `pnpm setup:yt-dlp`。

### 打包路径

- 开发环境：`<appPath>/runtime/yt-dlp/<platform>/yt-dlp[.exe]`。
- 生产环境：`<process.resourcesPath>/yt-dlp/<platform>/yt-dlp[.exe]`。
- `electron-builder.json5` 通过 `extraResources` 复制整个 `runtime/yt-dlp`。
- macOS 官方文件本身是 x64+arm64 Universal Mach-O；`x64ArchFiles: 'Contents/Resources/yt-dlp/**'` 告诉 Electron Universal 合并器只保留一份相同资源。
- 用户运行成品 App 时不需要 Python、Homebrew 或全局 yt-dlp。
