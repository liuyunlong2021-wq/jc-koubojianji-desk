# 影片拉片工作台按钮与后端逻辑

> 按 2026-08-24 当前代码与本轮用户验收结论记录。按钮文案与实现不一致时，以真实调用链和落盘状态为准；当前功能用于拆镜、分析和导出文档，不生成重新剪辑的成片。

## 产品定位与总流程

影片拉片与口播剪辑属于同一个 APP，共用应用设置、API Key 和文本模型，但使用独立路由、页面、项目历史和拉片状态文件。

```text
选择项目 → 上传影片 → 自动切镜 → 人工校正 → 确认镜头切分
                                              ├→ 图片分析 → 资产分析/画面反推/资产提示词/图片文档
                                              └→ 视频反推 → 全片总览 → 按时长拼装/完整提示词文档
```

切镜的目的不是交付逐镜视频，而是把长视频变成 Gemini 更容易准确理解的短 MP4。模型直接读取视频片段，首帧、中间帧和尾帧用于画面提示词与跨镜资产识别。

## 调用、状态与存储

- 页面：`src/views/FilmBreakdownDesk/index.vue`。
- 纯逻辑与文档拼装：`src/runtime/filmBreakdown.ts`。
- preload / IPC：`electron/preload.ts`、`electron/ipc.ts`。
- 项目、FFmpeg 与任务编排：`electron/film-breakdown-project.ts`。
- Gemini 请求与结构化响应：`electron/talking-head-cloud.ts`。
- 应用默认模型：`gemini-3.7-flash`；拉片与口播共用 `AppSettingsDialog` 和同一份应用级模型设置。
- JSON 是工作状态真源；`影片拉片.md` 是每次写状态时同步重建的可读投影，不反向解析。

项目根下使用以下目录：

```text
.raw/jc-media/
├── 视频/
│   ├── 拉片原片.<扩展名>
│   └── 拉片分析片段/shot-编号-开始毫秒-结束毫秒.mp4
├── 图片/
│   ├── 拉片中间帧/
│   └── 拉片帧/*-start.jpg、*-middle.jpg、*-end.jpg
└── 文档/
    ├── 拉片项目.json
    └── 影片拉片.md
```

状态和 Markdown 使用临时文件后重命名的方式写入。APP 异常退出后，读取项目时会把遗留的 `running` 镜头或资产恢复为 `pending`；若任一确认帧文件缺失，则自动取消 `boundariesConfirmed`，不允许继续分析不存在的素材。

## 原片播放器与项目输入

| 操作 | 实际逻辑 |
| --- | --- |
| 上传影片 | 支持 MP4、MOV、M4V、MKV、AVI、WebM。FFmpeg 读取视频轨并解析真实时长；不可读或无有效时长时拒绝。没有项目时会继续要求选择项目目录。 |
| 更换影片 | 走与上传相同链路，原子复制为 `视频/拉片原片.<扩展名>` 并计算 SHA-256。随后删除旧分析片段、旧中间帧和旧三帧目录，清空镜头、资产、总览及确认状态。 |
| 原生播放控件 | Chromium `<video controls>` 负责播放、暂停和拖动；播放器 URL 带原片指纹作为缓存版本参数。 |
| 点击镜头行 | 从该镜头开始时间播放，到结束前约 35ms 自动暂停，避免越入下一镜；播放头同步到右栏校正时间。 |

上传新原片属于全量失效操作，旧的镜头分析和总览不能跨原片复用。

## 镜头检测

| 按钮/控件 | 前置条件 | 后端逻辑与结果 |
| --- | --- | --- |
| 切镜灵敏度 | 可选“灵敏 `.2` / 标准 `.3` / 稳健 `.4`” | 值越低越容易检出画面变化；后端只接受这三个固定阈值。 |
| 自动切镜 | 必须已有原片，且当前没有切镜、确认、图片、视频或总览任务 | 先按用户阈值执行 FFmpeg `select=gt(scene,threshold),showinfo` 并解析 `pts_time`。若不超过 30 秒的短片没有检出任何切点，自动以 `.12` 做一次敏感补检；补检候选使用 500ms 最小镜头长度过滤细碎动画。程序补入 0 和原片结束点，去重、排序并生成连续 `shot-001...`。 |

自动切镜只比较相邻画面的像素变化，不依赖角色、场景或道具语义，因此没有人物、只有包装、文字或插画的广告片同样可以检测。短片敏感补检只在主检测得到 0 个切点时运行：主检测已经找到切点时保持原结果，超过 30 秒的片子也不增加第二次扫描。渐变、叠化和持续形变仍可能弱于阈值，因此自动切镜始终只是候选边界，不是最终裁决。

重新执行自动切镜会清空人工边界、资产目录、全片总览和逐镜结果，并把 `boundariesConfirmed` 设为 `false`。

## 播放头人工校正

五个编辑按钮先在前端通过 `editFilmBreakdownShots()` 计算，再由后端校验完整时间轴并保存。合法时间轴必须从 0 开始、连续无空洞、最后覆盖原片真实结束点，且 ID 按时间顺序连续编号。

| 按钮 | 精确规则 |
| --- | --- |
| 在当前位置拆分 | 播放头必须位于所选镜头内部，并与两端各保持至少 120ms；拆成两镜，两个新片段的媒体与分析结果清空。 |
| 与下一镜合并 | 所选镜头必须存在下一镜；两段合为一个连续镜头，合并结果的媒体与分析结果清空。 |
| 设为所选镜头开始 | 必须存在上一镜；播放头同时成为上一镜结束和本镜开始，两侧均须至少 120ms。 |
| 设为所选镜头结束 | 必须存在下一镜；播放头同时成为本镜结束和下一镜开始，两侧均须至少 120ms。 |
| 删除所选镜头 | 不在时间轴留下空洞：优先并入上一镜；删除第一镜时并入下一镜。只剩一镜时不执行。 |

任一人工校正都会重新编号镜头，清空全片资产和全片总览，并要求重新点击“确认镜头切分”。

## 确认镜头切分

“确认镜头切分”只有在已有镜头、尚未确认且没有其他任务时可用。后端逐镜执行：

1. 校验时间轴完整连续。
2. 按当前开始/结束点转码真实 720p H.264 MP4，音频存在时保留并转为 AAC 96kbps。
3. 文件名包含镜头 ID 和精确起止毫秒，已存在且对应当前边界的片段和三帧可复用。
4. 提取兼容用中间帧，以及首帧、中间帧、尾帧三张 JPEG；尾帧取结束前 80ms，避免混入下一镜开头。
5. 每完成一镜立即写状态，全部成功后设置 `boundariesConfirmed = true`。

这一步是所有图片与视频 AI 分析的共同门禁。确认失败时不冒充已确认；已经落盘的前序镜头可在再次确认时复用。

## 中栏三个结果视图

| 视图/操作 | 实际作用 |
| --- | --- |
| 镜头画面 | 显示每镜 ID、毫秒时间码、时长、首帧缩略图、分析状态、错误、视频提示词/剧本和已生成的首中尾帧图片提示词。文本框 `change` 时立即保存。 |
| 资产库 | 资产分析后开放；显示代表帧、名称、类别、出现帧数、识别描述、提示词、状态与单项错误。人工修改提示词后立即保存；非空改为 `ready`，清空则回到 `pending`。 |
| 项目总览 | 生成总览后开放；可编辑叙事主线、灯光哲学、色彩分级、时间状态语法、场所、环境音、人群规则、技术约束及每镜功能。字段失焦即校验并保存。 |

逐镜视频提示词被人工修改后，旧全片总览会立即失效并从界面移除，防止新逐镜内容与旧总览混合导出。单独修改剧本、图片提示词或资产提示词不影响全片总览。

## 左栏资产选择

“本片资产”由资产分析建立，按角色、场景和关键道具分组。每项显示一张代表帧和全片出现次数。

- 分组复选框执行该类全选/全不选。
- 单项复选框切换一个资产。
- 每次选择变化立即写入 `拉片项目.json`。
- “生成资产提示词”计数只统计已选且尚未 `ready` 的资产；已生成项不会重复付费。
- 资产生成成功后自动取消该项选择；失败项保留错误，可再次选择/生成。

## 图片分析按钮

### 资产分析

前置条件是镜头切分已确认，且当前没有其他模型任务。后端读取每一镜的首帧、中间帧和尾帧，把全片帧一次提交给 Gemini，要求：

- 只识别可复用的角色、场景和关键道具。
- 同一对象跨镜头合并为一项，并返回每个出现位置的 `shotId + start|middle|end`。
- 普通桌椅和无关陈设不冒充关键道具；只记录可见特征，不猜身份或剧情。
- 无效类别、空名称、空描述、无真实帧的出现位置会被程序过滤。

重新资产分析时，同类别同名称资产会保留旧 `assetId`、用户选择、已生成提示词、状态和错误；新的描述、出现位置和代表帧按本次识别更新。

### 画面反推范围

首帧、中间帧、尾帧为多选，默认只选首帧，至少保留一项。该控件只决定下一次“反推全片所选画面”的输入范围。

### 反推全片所选画面

按镜头顺序、再按所选帧位置串行调用 Gemini。已经存在非空提示词的镜头帧直接跳过；每生成一张立即保存，因此停止或失败不会丢掉前面结果。

画面 Prompt 要求只输出一条可直接生图的中文正文，并覆盖画幅、精确文字、人物国别/年龄段/五官/发型、具体场景物件、材质、光线、调色板、风格锚点、相机语境、复杂画面层次和否定约束；没有看到的信息不得虚构。

### 生成资产提示词

只处理左栏已选且未完成资产。一个资产可能在很多镜头/角度出现，程序按时间排序后最多均匀抽取 6 张参考帧，使参考覆盖全片出现范围，而不是只取开头相邻画面。

角色资产使用《MV生成规范》的有参考图三视图：

- 16:9 横向三格，同一角色和同一造型。
- 左格为 0° 正面无头全身；中格为 180° 正后方带头全身。
- 右格为相机位于一侧前方约 30°–35° 的斜侧齐胸身份近景，锁定双眼、鼻梁侧线、颧骨、下颌线、耳侧发际线和身份标记。
- 三格使用 18% 中灰背景、无方向无阴影正面照明、统一曝光和真实照片质感。

场景资产使用《MV生成规范》的空镜规则：

- 默认 3/4 斜角俯拍，相机位于空间一侧前上方约 30°–45°；多数清晰参考图明确为其他机位时才修正。
- 先还原空间结构、入口出口和视线，再分前景/中景/远景，补天空或天花板、材质、时代痕迹、灯光、色温、介质、对比度、摄影质感和情绪。
- 强制纯空镜无人物，并排除现代违和物、重复物件、错误透视、漂浮物体、CGI 塑料感和虚假文字。

道具资产按复杂度分流：

- 武器、机械、交通工具、复杂工具和长期复用核心道具：16:9、4K、3×2 六视图，包含正背左右上下、尺寸、材质、表面处理、固定磨损、方向锚点、摄影棚、灯光、标签及一致性锁定。
- 老照片、信件、票据等平面文件：简化为正面、背面、侧面/特写三图；文字只能来自参考图，无法确认时不虚构。

### 导出图片文档

存在任一首中尾帧图片提示词，或任一 `ready` 资产提示词时开放。可导出 Markdown 或 TXT：先按镜头时间输出画面提示词，再按角色、场景、关键道具输出完成的资产提示词；不夹带视频提示词或剧本。TXT 只去掉 Markdown 标题标记，正文保持一致。

### 停止图片分析

当前图片任务运行时显示。调用项目级 `AbortController.abort()`；已完成并写入的结果保留，当前请求停止，下一次会跳过已完成结果并继续缺失项。

## 视频反推按钮

### 输出模板

可以单选或多选，至少一项：

- 视频提示词：逐镜读取真实 MP4，固定输出镜头时间、功能标签、特效、摄影、运动、动作、SFX、可选对白、出口和转场；只描述真实可见可听内容。
- 剧本：按 `#第X集 / ## 场X-Y / 时间 / 场景 / 人物 / 道具 / △动作 / 台词` 格式反推；未知集场用 X，不为凑字数虚构对白、剧情或付费卡点。

### 开始视频反推

前置条件：已确认镜头、有镜头、至少选择一个模板、已配置 API Key，且图片或总览任务未运行。

后端按镜头串行执行。每镜只请求所选模板中仍为空的部分，因此再次点击是断点续跑和失败重试，不覆盖已完成模板。真实分析片段以 Base64 `video_url` 提交；单片超过 60MiB 时该镜失败并提示提高切镜灵敏度。

单镜执行过程：先写 `running`；模型成功后合并结果并写 `ready`；失败写 `failed + error`，继续下一镜；每镜结束立即写项目。模型返回过长或结构异常时，云端解析会报告明确任务和响应摘要，不把残缺文本当成功。

### 停止视频反推

终止当前项目的分析控制器。已完成镜头保留；再次开始时跳过已有结果，只处理缺失模板。

### 导出视频文档

所选模板中至少存在一个结果且当前未分析时开放。按镜头时间顺序导出所选的“视频提示词”和/或“剧本”；没有结果的模板/镜头不输出。支持 Markdown 与 TXT，不包含图片与资产结果。

## 全片总览与完整提示词

### 片段时长

使用 4–30 秒、步长 1 秒的带刻度滑块，默认 15 秒。界面上方显示当前值，滑块保留 4、10、15、20、25、30 刻度，不常驻显示重复的拇指数值浮层。

该值是目标时长而非硬切上限。程序绝不截断一个已确认镜头，而是在前后完整镜头边界中选择最接近目标时长的组合，所以实际片段可能略短或略长。

### 生成/更新全片总览

所有镜头都已有视频提示词后开放。Gemini 一次读取全片逐镜提示词、时间码和资产出现关系，返回：

- 叙事主线。
- 灯光哲学。
- 色彩分级。
- 时间状态语法。
- 场所。
- 环境音。
- 人群规则。
- 技术约束数组。
- 每个 `shotId` 的镜头功能。

叙事、灯光、色彩、场所、环境音和至少一条技术约束为必填；镜头功能允许为空。生成成功后自动切换到“项目总览”，用户可以逐项修改并保存。

### 导出完整视频提示词

必须同时具备有效全片总览和每镜视频提示词。导出不是再次调用模型拼装，而是程序确定性完成：

1. 按目标时长寻找最近完整镜头边界，形成多个片段。
2. 每个片段的镜头时间从 0 重新计时，镜头编号也从 1 开始。
3. 收集本片段实际出现的资产并生成 `@Image1 = 资产名称` 映射。
4. `@Image` 在每个片段中独立从 1 编号；这是给用户手工上传参考图使用的局部占位符，不要求全片统一编号。
5. 把该镜头涉及的占位符插入“参考资产”行。
6. 拼装叙事主线、灯光哲学、色彩分级、时间规则、场所、环境音、人群、逐镜正文和技术约束。

支持 Markdown 与 TXT，默认文件名包含项目名和滑块目标秒数。导出对话框取消时不写文件。

## 总览失效规则

| 变化 | 失效结果 |
| --- | --- |
| 更换原片 | 清空镜头、资产、总览、确认状态和旧媒体片段。 |
| 重新自动切镜 | 清空人工边界下游、资产、总览和逐镜结果。 |
| 任一人工镜头校正 | 取消确认，清空全片资产和总览；受影响镜头分析结果按编辑逻辑重置。 |
| 人工修改视频提示词 | 保存新逐镜内容并清空旧总览，必须重新生成总览后才能完整导出。 |
| 人工修改剧本 | 只保存剧本，不影响总览。 |
| 修改图片/资产提示词或选择状态 | 只更新对应图片数据，不影响视频总览。 |
| 编辑项目总览 | 规范化并覆盖保存总览，不重新调用模型。 |

## 任务互斥、停止与错误恢复

- 同一项目只维护一个分析控制器；开始新的模型任务会终止同项目旧控制器。
- UI 在切镜、确认、图片、视频和总览任务之间设置互斥门禁，正常操作不会并发启动两个付费任务。
- 停止按钮作用于当前项目的分析控制器；停止不是删除，已原子保存的镜头/帧/资产继续保留。
- 图片任务失败时前端重载项目，以落盘 JSON 为准恢复进度。
- 视频单镜或资产单项失败会记录错误并继续后续项目；缺少本地片段/帧等结构错误则明确报错。
- API Key 缺失时所有 Gemini 任务在请求前阻止；FFmpeg 切镜和片段生成不需要 API Key。
